# 股票模拟交易小游戏 —— 设计文档（MVP：子项目 A + B）

- 日期：2026-05-29
- 状态：已通过 brainstorming，待 user review
- 覆盖范围：子项目 **A（核心游戏引擎 + Web 客户端）** 与 **B（数据采集与关卡生成管线，首版仅中国 A 股）**

---

## 1. 背景与产品定位

做一款"类股票"小游戏：用真实历史行情切片作为关卡，玩家在只看到一段历史 K 线的情况下，逐日决策加仓 / 卖出 / 持有，体验暴涨的爽感与停牌、ST、退市的痛感，从而形成强记忆点、促进分享传播。

完整产品由 5 个子项目组成，按依赖排序：

| 子项目 | 内容 | 依赖 |
|---|---|---|
| **A. 核心游戏引擎 + Web 客户端（单机 MVP）** | 发牌 → 看前 10 天 K 线 → 逐日决策 → 结算 → 结局复盘 | 无（脊柱） |
| **B. 数据采集与关卡管线** | 抓行情、清洗、复权、脱敏、算指标、切关卡包 | 可与 A 并行 |
| **C. 后端服务 + 账号体系** | 账号、存档、资金/战绩持久化 | A 玩法稳定后 |
| **D. 排行榜 + 社交分享** | 战绩分享卡、好友 PK、裂变 | C |
| **E. 多端适配** | 编译到各家小程序 + Steam 壳 | A/C |

**本文档只覆盖 A + B。** C/D/E 后续各自走 spec → 计划 → 实现循环。

平台目标：**Web 优先**，后续移植微信 / 抖音 / 小红书小程序，乃至 Steam。

---

## 2. 总体架构（A 与 B 解耦）

```
[B: Python 离线数据管线]            [A: Taro/React 纯前端游戏]
 akshare/baostock 采集               关卡加载器
   → 复权(后复权)                    → 游戏引擎(纯函数状态机)
   → 脱敏(去标识/转相对日序)         → klinecharts K线视图
   → 指标预计算                      → 交易面板(滑条选量)
   → 切关卡 + 标事件                 → 结算/复盘(事后揭盘)
        │                                  ▲
        └────►  关卡包 (静态 JSON + 索引)  ─┘
```

- **MVP 无后端**：B 产出静态关卡包，A 直接加载即玩，便于各自独立测试。
- 关卡包是 A 与 B 之间唯一的契约接口（见 §5 数据契约）。
- 后端 / 账号（C）在玩法稳定后接入，A 已预留对接点。

### 技术栈
- **前端 A**：Taro(React) + klinecharts。一套 React 代码可编译到 Web 与各家小程序，klinecharts 支持小程序 canvas。Steam 后续用 Electron/Tauri 套壳 Web 构建。
- **数据管线 B**：Python + akshare/baostock。

## 3. 核心玩法规则

| 维度 | 规则 |
|---|---|
| 局结构 | **单股**（一局随机抽一只匿名股票的一段历史）；架构预留组合多股扩展 |
| 初始展示 | 前 **10** 个交易日的完整 K 线与指标 |
| 局长度 | **随机 30–60** 个交易日（含初始 10 天） |
| 决策节奏 | **每日一决策**：每揭示 1 个新交易日，玩家做一次加仓 / 卖出 / 持有 |
| 交易额度 | **滑条自由选量**：买入按现金百分比、卖出按持仓百分比 |
| ⚙️ 初始资金 | 10 万虚拟币 |
| ⚙️ 交易成本 | 简化小额手续费（贴近真实但不喧宾夺主），可配置为 0 |
| ⚙️ 目标 | 最大化结束时**总资产**（现金 + 持仓市值）；展示收益率 % 与评级 S/A/B/C/D |
| 可见指标 | K 线 + 成交量；区间高/低/涨跌幅；换手率/量比；均线(MA5/10/20)/MACD/RSI |
| 脱敏 | 玩家全程看不到股票名称、代码、真实日期 |

### 黑天鹅事件（来自真实数据，事后才揭盘）

- **停牌**：停牌期间价格冻结、无法买卖；复牌后可能高开/低开（跳空）。
  - **超长停牌**：若停牌时长超过玩家剩余交易日，显示一个"跳到复牌首日"按钮（**仅停牌时出现**），点击后直接推进到复牌后第一个交易日。
- **退市**：买到退市股，持仓归零 / 锁死，"永远无法翻身"。
- **ST**：进入 ST 后每日涨跌幅收窄（如 ±5%）。
- **揭盘时机**：游戏过程中不直接标注 "ST / 退市"（保持悬念与脱敏），仅以异常指标暗示；**结局复盘**时才揭示真相。

### 结局复盘
- 最终总资产、收益率%、评级。
- 与"全程持有不动"（buy & hold）基准对比，增强回味。
- 事后揭盘：这只股票其实发生了什么（ST/退市/停牌真相）。

## 4. 子项目 B —— 数据管线（首版：中国 A 股）

### 模块（每个职责单一、可独立测试）
1. **Fetcher**：日 K 行情、股本/流通股、ST/退市/停牌状态（akshare/baostock）。支持断点续采与限流重试。
2. **Adjuster**：后复权处理，避免除权跳空误导。
3. **Anonymizer**：去掉名称/代码/真实日期 → 转"相对第 N 日"；仅保留 开/高/低/收/量/换手率/量比/涨跌停状态/事件标记。
4. **Indicator precompute**：MA5/10/20、MACD、RSI、区间高低、涨跌幅。
5. **Level builder**：切片为关卡（随机 30–60 日窗口，前 10 日为初始展示）；将真实停牌/ST/退市事件写入 metadata；打难度/结局类型标签。
6. **Output**：按关卡分文件的 JSON + 一个索引文件。

### ⚙️ MVP 数据量
先抽一批覆盖多种结局的种子关卡（暴涨 / 暴跌 / 退市 / 长期停牌 / 横盘各若干只），保证体验多样性。全市场全量是 B 的完整目标，可分批跑，不阻塞 A 的玩法验证。

---

## 5. 数据契约：关卡包结构（A↔B 唯一接口）

> 字段为设计意图描述，实现时在 plan 阶段定稿确切 schema 与类型。

**索引文件 `index.json`**：关卡列表，每项含 `levelId`、`difficulty`、`outcomeTags`（如 `surge`/`crash`/`delisted`/`long-halt`/`flat`）、`fileRef`、`totalDays`。

**单关卡文件 `level_<id>.json`**：
- `levelId`、`totalDays`（30–60）、`revealDays`（=10）、`startCash`
- `days[]`：逐日数组，每项含相对日序、开/高/低/收/量、换手率、量比、预计算指标、当日 `tradable`（停牌为 false）、`priceLimit`（ST 时收窄）。
- `events[]`：事件标记（类型 = halt/st/delist、起止相对日、复牌相对日等），**用于结局揭盘**。
- `reveal`：结局揭盘文案数据（这只股票真实发生了什么）。

脱敏校验：关卡包中不得包含任何可还原股票真实身份的字段（名称、代码、绝对日期）。

## 6. 子项目 A —— 游戏客户端

### 模块
1. **关卡加载器**：读 `index.json`，随机或按策略选一关并加载关卡文件。
2. **游戏引擎（纯函数状态机，核心）**：管理现金/持仓/天数推进/买卖结算/事件处理。完全无 UI 依赖，便于全量单测。状态转移包括：
   - 推进一日（揭示下一日）
   - 买入（按现金%，扣手续费）/ 卖出（按持仓%）/ 持有
   - 停牌日：禁用交易、价格冻结
   - 超长停牌：暴露"跳复牌"动作
   - ST 日：限制当日涨跌幅
   - 退市：持仓归零/锁定，终结
   - 结算：计算总资产、收益率、评级、buy&hold 基准
3. **K 线视图**：klinecharts 渲染逐日揭示的 K 线 + 成交量 + 均线 + 指标。
4. **交易面板**：滑条选量、买/卖/持有按钮、现金与持仓实时展示、"跳复牌"按钮（条件出现）。
5. **结算/复盘视图**：总资产、收益率、评级、buy&hold 对比、事后揭盘。
6. **预留扩展点**：组合多股、后端对接。

---

## 7. 错误处理

- 关卡数据损坏/字段缺失 → 跳过该关并记日志，加载下一关。
- B 采集限流/失败 → 重试 + 断点续采。
- 停牌超剩余交易日 → "跳到复牌首日"按钮（已定义）。
- 退市后 → 锁定所有交易操作并提示，进入结算。
- 关卡包加载失败 → 友好报错并允许重试/换关。

## 8. 测试策略

- **B**：清洗/复权/脱敏/指标计算单元测试；关卡包 schema 校验（脱敏断言：无身份字段）；抽样人工核对真实事件标记正确。
- **A**：游戏引擎纯函数**全覆盖**单测（买卖结算、手续费、停牌冻结、退市归零、ST 限幅、跳复牌边界、随机局长边界、结算与评级）；交易面板/图表组件交互测试；端到端一局完整流程冒烟测试。

## 9. 明确不做（YAGNI，留给后续子项目）

- 排行榜、社交分享、好友 PK（D）
- 小程序 / Steam 实际打包（E，本期仅保证 Taro 技术栈不堵死移植）
- 组合多股玩法（仅预留架构扩展点）
- 中国 A 股以外的市场（B 后续分批补齐美/日/韩）

## 10. 交付拆分建议

A 与 B 共用本设计，但可拆成两份实现计划并行推进：
- **Plan B**：数据管线 + 一批种子关卡包（产出 A 可消费的 `index.json` + 关卡文件）。
- **Plan A**：游戏引擎 + Web 客户端（先用少量手造/B 早期产出的关卡包驱动开发）。

二者通过 §5 数据契约解耦，可独立开发与测试。
